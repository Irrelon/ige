# IGE 3D Renderer - Development Plan

## Summary

The goal is unchanged from the original plan: one renderer that draws 2D sprites and 3D models with the same entity API,
keeping IGE simple to use. The route has changed. Instead of building on Three.js, IGE now has its own WebGL renderer,
`IgeWebGlRenderer`, which is the primary 3D path. `IgeThreeJsRenderer` remains as an incomplete experiment and is not
being developed.

The current driver for renderer work is a **split-screen zombie ARPG** (up to four local players, large hordes). The
`src/examples/zombie-game` example is a playable prototype of that game and doubles as the renderer's integration test
and performance benchmark. `src/examples/hex-realms` (a large hex-map strategy prototype, in progress) is a second
test bed; its README lists the engine gaps found while building it (see "Engine gaps from Hex Realms" below).

Guides: [`guides/webgl-models.md`](guides/webgl-models.md) (3D models and characters) and
[`guides/2d-on-webgl.md`](guides/2d-on-webgl.md) (moving a 2D project to the WebGL renderer).

## Why a custom WebGL renderer

- IGE's scene graph, viewports and transforms map directly onto the renderer; nothing has to be mirrored into a second
  scene graph.
- The frame pipeline can be shaped for IGE's needs, e.g. collecting the scene once and drawing it into several
  split-screen viewports.
- No large runtime dependency and a smaller bundle.
- Full control over shaders, batching and instancing.

The cost is that features Three.js provides for free (loaders, materials, post-processing) have to be built, so the
plan prioritises what the target games need.

## Where things stand (November 2026)

### Done

| Area | What exists |
|------|-------------|
| Core | WebGL 2 with a verified WebGL 1 fallback (`preferredWebGlVersion(1)` to test it), shader library with instanced variants, state and uniform caching |
| Frame pipeline | Scene collected once per frame; each viewport culls, renders its own directional shadow map (or shares one when split-screen views are close), then draws opaque batches front to back, ground decals, transparent items, particles and debug lines. Point light shadows render once per frame, culled per cube face |
| Split screen, HUD and picking | Per-viewport cameras and shadow maps, `IgeViewportOverlay` (DOM HUD clipped to each view), `worldToScreen()`, `screenToWorldRay()`, `screenToGround()`, `screenToHeightfield()`, `viewportAt()`, `cameraMatrices()`, `maxPixelRatio()` |
| Models | GLTF/GLB loader; `IgeEntity.model()` sets up every mesh, material, texture, node transform, skeleton and animation clip; per-entity material overrides via `_materialData`; vertex colours; double-sided materials; `attachToBone()` and `bonePosition()` |
| Animation | Skeletal animation with cross-fades and blending, `playAnimation()`, a shared pose cache for crowds, off-screen animation culling, clips from separate files retargeted by bone name (`model(..., { animations })`, `retargetClips()`) |
| Performance | GPU instancing for static and skinned meshes, world-space frustum culling, cached entity transforms, level of detail for models and plain geometry (`lod()`, generated by `IgeMeshSimplifier` or authored), opt-in back-face culling, cached static shadow casters (`shadowCaching()`), render on demand (`ige.engine.renderOnDemand()`), `stats()` |
| Resources | `releaseGeometry()` / `releaseTexture()` (also on `IgeTexture.destroy()`); no CPU copies of uploaded geometry kept |
| Lighting | Ambient, directional, point (up to 8) and spot (up to 4) lights; shadowed directional light and up to 2 shadowed point lights; linear/exp2 fog |
| Effects | `IgeParticleSystem3d`, `IgeDecalSystem3d` (multiply-blended ground stains), sprite sheet cells, tint, additive blending and billboard modes |
| Camera | Perspective and orthographic projection, up vector and look direction, `lookAtPoint()`, presets (`isometric`, `isometric45`, `topDown`, `sideScroller`, `screen2d`) |
| 2D | `screen2d` camera (Canvas 2D style: y down, one unit per pixel, zoom by camera scale), smart textures drawn per entity (redrawn every frame, or when dirty with `cache(true)`), flat 2D sprites with full 2D transforms, split screen |
| Debugging | `debugDraw({ bounds, shadowFrustum })` (bounds coloured by LOD level), `debugLine()` |

### Measured

On the development machine (Apple silicon, Chrome):

- Zombie demo, four viewports: 120 zombies at about 66 fps at a 1.5 pixel ratio. With 200 zombies the frame went
  from about 43 ms to about 15 ms after the instancing, culling and transform work.
- LOD cuts the demo's submitted triangles from about 4.1 to 1.9 million per frame (GPU time about a quarter lower);
  back-face culling cuts GPU time by about a fifth (7.7 to 6.0 ms with 60 zombies).
- Shadow caching: in Hex Realms a camera pan drops from 14-15 shadow draw calls per frame to 1; the zombie demo's shared
  shadow map from 29 to 5.
- Per-face point shadow culling: the lighting example from 130 to 51 shadow draw calls and 7.0 to 3.4 million
  triangles per frame; with its `?lod=1` option the shadow maps use lighter meshes and it drops to 1.6 million.
- Animation costs about 0.75 ms per frame for 150 zombies, so lowering the update rate of distant characters is not
  worth doing yet.

### Verified

- WebGL 1 (`?webgl=1` on the zombie and lighting examples): everything renders with no GL errors, including skinned
  characters, shadows, decals, particles and the overlay (two bugs found and fixed: shadows were blended away, and
  meshes over 65535 vertices didn't draw).
- Multiple viewports: the 4-view zombie demo, the 2-view 2D example (`webGl2d?split=1`), and racing-game's
  two-player split screen.
- Hex Realms runs on the current engine; back-face culling, shadow caching and render on demand were tried on it from
  the console (tiles style).

### Not verified

- Gamepad input has only been tested with simulated keyboard input.
- Pointer events on entities (mouse over and click picking), composite caching, canvas filters and `IgeFontEntity` text
  on the WebGL renderer.

## Next steps

### Needs your input

- **Game assets.** Zombie and player models with walk, run, attack, hit and death clips, to be generated with an
  online service. The engine side is ready: clips in separate files load through `model(..., { animations })`, dense
  meshes get `lod` levels, and weapons attach with `attachToBone()`. When the assets arrive, check that the rig and
  clips load and play, and whether an A-pose model needs clips authored for a T-pose rig (posture differences aren't
  corrected).
- **Isometric 2D games.** Canvas 2D iso games place the ground on x/y with z up; the WebGL renderer is y-up 3D. Decide
  whether the engine should map iso-mode entities automatically (e.g. render x/y/z as x/z/y under an iso camera) or
  whether iso games move to a 3D layout.
- **Physics.** Jolt physics integration is on the `es6-typescript-3d-jolt-physics` branch (not merged; last commit
  "Physics, not really working"). Decide whether to finish it on that branch or start again on top of the current
  engine.
- **Gamepads.** Test with real controllers.

### Engine work remaining

- Pointer events on entities with the WebGL renderer (picking against sprites and meshes per viewport).
- Decals on walls and uneven terrain (they currently lie flat at a given height).
- Revisit animation update rates only if profiling shows a need.

## Engine gaps from Hex Realms

Status of the notes in `src/examples/hex-realms/README.md`:

| # | Gap | Status |
|---|-----|--------|
| 1 | Vertex colours ignored by the lit shaders | Done: geometry `colors` (RGB or RGBA) multiply the base colour |
| 2 | LOD only for model parts | Done: `lod()` works on `_geometryData` entities, generated (`ratio`) or authored (`geometry`) |
| 3 | No public way to free geometry or textures | Done: `renderer.releaseGeometry()` / `releaseTexture()`; `IgeTexture.destroy()` frees its GPU copy |
| 4 | Three copies of every geometry | Partly: the engine's interleaved copy is no longer kept. The caller's arrays still are, because LOD generation and re-upload after a release read them |
| 5 | Shadow map redrawn every frame | Done: `renderer.shadowCaching(true)` |
| 6 | Back-face culling never enabled | Done, opt-in: `renderer.backFaceCulling(true)`; `doubleSided` materials are exempt |
| 7 | Picking only against a flat plane | Done: `renderer.screenToHeightfield(viewport, x, y, heightAt, { minHeight, maxHeight, step })` |
| 8 | Every geometry creation logged | Done: no longer logged |
| 9 | No automatic render-on-demand | Done: `ige.engine.renderOnDemand(true)`; call `manualRender()` after material or texture changes |

## Open questions

- Should materials get a public API (e.g. `entity.material({...})`) instead of assigning `_materialData`?
- Unified asset loading (textures and models through one loader) is still only an idea.
- Should `IgeCanvas2dRenderer` remain the default for 2D projects, or should the WebGL renderer replace it?
